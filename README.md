# RBE203 Lab — 双轮平衡车

基于 Arduino Uno 的双轮平衡车实验项目，包含控制程序、硬件诊断程序、依赖库和实验资料。

## 项目内容

| 路径 | 内容 |
| --- | --- |
| `two_wheel_robot/` | 平衡车主程序及辅助源码 |
| `robot_diagnostic/` | MPU6050 和电机诊断程序 |
| `dependencies/libraries/` | 项目使用的 Arduino 依赖库 |
| `dependencies/*.zip` | 依赖库压缩包 |
| `dependencies/backups/` | 本地已有的历史源码备份；当前程序位于 `two_wheel_robot/` |
| `库文件/` | 随实验提供的库文件和使用说明 |
| `library_for_two_wheel_robot.rar` | 原始库文件压缩包 |
| `Stabilization of two-wheel robot.pdf` | 实验参考资料 |

`tmp/` 中的编译产物、串口日志和临时分析文件不纳入版本控制。

## 使用

1. 在 Arduino IDE 中安装 Arduino AVR Boards，选择 **Arduino Uno**。
2. 使用 `库文件/` 中课程提供的库。主要依赖为 PinChangeInt、MsTimer2、BalanceCar、KalmanFilter、I2Cdev 和 MPU6050；Wire 由开发板核心提供。当前工程没有修改这些课程库，新增的控制与通信代码位于主程序目录。
3. 打开 `two_wheel_robot/two_wheel_robot.ino` 并编译。诊断程序的入口为 `robot_diagnostic/robot_diagnostic.ino`。
4. 串口监视器波特率为 **9600**。

当前源码包含固定的陀螺仪零偏及控制参数；更换硬件后需重新核对。运行电机诊断前应将车轮悬空，诊断程序不执行平衡控制。

## HC-06 蓝牙左摇杆

车端版本为 `v6.0-hc06-joystick`，本次只修改和编译代码，需自行上传。

1. 上传 `two_wheel_robot/two_wheel_robot.ino`。程序使用 Uno 硬件串口 D0/RX、D1/TX，波特率 9600；车板的 Bluetooth 插座需要连接这一串口。USB 和蓝牙共用串口，上传时按车板设计切换到 USB 或断电后拔下蓝牙模块，避免模块干扰下载；恢复蓝牙运行时断电后接回模块。
2. 在 Windows 蓝牙设置中配对 **HC-06**，配对码 **1234**。找到 Windows 为它分配的蓝牙串行 **出站 COM 端口**。USB CH340 的 COM3 是有线连接，不等同于蓝牙端口。
3. 先关闭旧摇杆窗口，再双击提速版 `tools/BluetoothJoystick-Faster.exe`，选择上一步的蓝牙 COM 端口并连接。也可双击 `tools/打开蓝牙摇杆.cmd`，在旧程序关闭后从当前源码编译并运行界面，无须安装 Python 包。初连先保持摇杆回中，日志出现 `bt=1` 后再推动。
4. 用鼠标拖动左摇杆上下控制目标速度，松开鼠标或按空格回中。界面失去焦点、断开、退出时也会尝试发送回中。初始幅度上限为 50，可用滑块在 0–100 间调整；如方向相反，回中后切换界面的反向选项。

界面每 100 ms 发送一次教程格式的 ASCII 文本帧，不需要换行：

```text
[joystick,LH,LV,RH,RV]
[joystick,0,0,0,0]      回中
[joystick,0,30,0,0]     左摇杆纵向 +30
[joystick,0,-30,0,0]    左摇杆纵向 -30
```

四个摇杆字段必须为 -100 至 100 的整数。本版只使用 **LV**，不响应 PID 滑杆、按键或右摇杆差速，不改变已调好的 PID 增益。左右方向和右摇杆暂不控制转向。

教程参考为 `D:\Files\平衡车入门教程资料\程序源码\程序源码-有注释版\平衡车程序\04-速度环实现行进\User\main.c` 中的 `joystick` 分支。教程的 `LV / 25.0` 使用轮轴转/秒；本车使用 **双轮总计数/40 ms**，因此只沿用协议和左纵向字段，不照搬其速度比例或 STM32 驱动。

当前映射在 `two_wheel_robot/two_wheel_robot.ino` 的 `JOYSTICK_MAX_SPEED`、`JOYSTICK_SPEED_SIGN`：

- `|LV| <= 5` 时目标为零。
- 其他值线性映射到满杆目标 ±15 计数/40 ms；例如 LV=30 对应约 +3.95，界面默认上限 LV=50 对应约 +7.11。
- 本次提速将固件满杆目标由 10 调为 15、界面默认幅度由 30 调为 50。两者更新后，默认拖到顶的目标约为原来的 2.7 倍；这是目标值倍率，实际速度需看 `v`。只重启新版界面、不上传新版固件时，默认目标约为 ±4.74。PID 增益保持现有设置。
- `JOYSTICK_SPEED_SIGN` 默认 +1，改为 -1 可反转目标方向；不要同时反转界面和固件两处。
- 收到无效帧不会更新目标或续期。超过 500 ms 没有有效帧，目标归零；重新连接后必须先回中。
- 倾倒、提起或 IMU 故障保护会清除运动目标；保护解除后同样要求先回中。回中/失联是令目标速度归零，电机继续执行平衡控制，不是切断电机，也不保证车辆瞬间静止。

每 0.5 秒的诊断输出保留，并增加：

| 字段 | 含义 |
| --- | --- |
| `LV` | 最近收到的左摇杆纵向值 |
| `vref` / `v` | 目标速度 / 实测滤波速度，均为计数/40 ms |
| `rx` | 完整合法摇杆帧的累计数 |
| `bt=0` | 尚未收到或已超时 |
| `bt=1` | 已回中解锁，可接收运动目标 |
| `bt=2` | 需要先回中 |
| `bt=3` | 车身或 IMU 保护正在阻止运动指令 |

首次验证需固定车身、车轮悬空，并检查 `rx`、`LV`、`vref` 与摇杆一致。悬空测试只验证通信与方向，实际地面行驶稳定性需另外验证。上传期间关闭控制界面和其他串口工具。
